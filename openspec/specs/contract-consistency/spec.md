# contract-consistency Specification

## Purpose
保证前后端出站契约在**字段名与字段类型**两个维度上始终一致：以后端 DTO 为类型与命名的真源，前端契约文件逐字镜像，由 fail-closed 的静态 Harness 闸门强制，且受管范围以可配置清单表达，能随项目扩展覆盖新模块，而不必每次改比对逻辑。

## Requirements

### Requirement: 字段名与类型双向一致

契约闸门 SHALL 对每一对受管的后端 DTO 与前端契约文件做双向比对：接口名集合 MUST 相等，共有接口的字段名集合 MUST 相等，且每个共有字段的两侧类型 MUST 落在同一张公开的 Java↔TS 类型映射上。任一侧出现对方没有的接口或字段、或共有字段类型不匹配时，闸门 MUST 以非 0 退出码结束并指出接口名与字段名。

#### Scenario: 两侧完全一致时通过

- **WHEN** 后端每个受管 record 的组件名与类型，与前端契约中同名 interface 的字段名与类型逐一匹配映射表
- **THEN** 闸门以退出码 0 结束，并报告受管接口数与字段数

#### Scenario: 字段类型漂移被判失败

- **WHEN** 后端把某字段从字符串类型改成整数类型，而前端契约仍声明为字符串
- **THEN** 闸门以非 0 退出码结束，并指出发生类型不匹配的接口名与字段名

#### Scenario: 字段名漂移仍被判失败

- **WHEN** 后端重命名某 record 组件，而前端契约未同步
- **THEN** 闸门以非 0 退出码结束，并分别列出后端有而前端无、前端有而后端无的字段

#### Scenario: 时间字段必须是 ISO-8601 字符串

- **WHEN** 后端某字段是时间戳类型（序列化为 ISO-8601 字符串），而前端契约把它声明为数值
- **THEN** 闸门以非 0 退出码结束，因为映射要求时间类型对应字符串而非数值

### Requirement: 未覆盖类型与解析失败一律 fail-closed

闸门 MUST NOT 在无法确定类型一致性时静默放行。出现映射表未覆盖的后端类型（如嵌套自定义类型、映射型、通配泛型），或某一侧解析不出任何接口形状时，闸门 MUST 以非 0 退出码结束并指出文件与位置，而不是把「两侧都为空」当成相等。

#### Scenario: 出现映射表未覆盖的类型

- **WHEN** 后端某字段类型不在公开映射表覆盖范围内
- **THEN** 闸门以非 0 退出码结束，并指出该类型出现所在的文件与字段，提示需要显式扩充映射表

#### Scenario: 一侧解析不出任何形状

- **WHEN** 后端未解析出任何受管接口，或前端契约未解析出任何接口
- **THEN** 闸门以非 0 退出码结束，声明是解析规则失配而非契约真的为空

### Requirement: 受管范围可配置并覆盖全部受管模块

受管的「后端 DTO ↔ 前端契约」配对 SHALL 以闸门内一处可配置清单表达。新增一对受管模块时，只向清单追加条目即可纳入同一套名字与类型比对，MUST NOT 需要改动比对逻辑本身。清单为空 MUST 以非 0 退出码结束。

#### Scenario: 追加一对受管模块

- **WHEN** 向可配置清单追加一对新的后端 DTO 与前端契约文件路径
- **THEN** 闸门对新增的这一对执行与既有模块相同的字段名与类型双向比对，无需修改比对逻辑

#### Scenario: 清单为空

- **WHEN** 可配置清单不含任何受管配对
- **THEN** 闸门以非 0 退出码结束，因为没有受管对象等价于保护形同虚设

### Requirement: 字段命名风格强制 camelCase

受管契约两侧的字段名 MUST 一律小写字母开头的 camelCase。任一侧出现蛇形或其它非 camelCase 命名，闸门 MUST 以非 0 退出码结束并指出字段名。

#### Scenario: 出现蛇形命名

- **WHEN** 后端 record 组件名或前端契约字段名含有下划线或以大写开头
- **THEN** 闸门以非 0 退出码结束，并指出不符合 camelCase 的字段名
