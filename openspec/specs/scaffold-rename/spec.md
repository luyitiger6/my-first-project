# scaffold-rename Specification

## Purpose

让脚手架模板的使用者能够把刻在仓库中的模板作者身份标识（项目名、groupId、包名）一键替换为自己的项目身份，并由 Harness 以退出码验证替换的完整性。

## Requirements

### Requirement: 脚手架支持参数化改名

脚手架 SHALL 提供改名脚本，接收新项目名与新包名参数，一次性替换全部硬编码点并将包目录重命名。

#### Scenario: 改名执行成功
- **WHEN** 在模板仓库执行改名脚本，并传入新项目名与新包名
- **THEN** 全部旧名硬编码点被替换为新值、包目录路径被重命名，脚本以退出码 0 结束

#### Scenario: 参数缺失
- **WHEN** 执行改名脚本但缺少任一必需参数
- **THEN** 脚本以非 0 退出码结束，并输出缺失参数的提示

### Requirement: 改名结果可被残留检查验证

改名完成后 SHALL 可通过扫描仓库确认旧名无残留。

#### Scenario: 残留检查通过
- **WHEN** 对改名完成的仓库执行旧名残留扫描
- **THEN** 扫描未发现旧名残留，检查以退出码 0 结束

#### Scenario: 残留检查失败
- **WHEN** 仓库中存在未被替换的旧名
- **THEN** 扫描命中旧名并输出位置，检查以非 0 退出码结束

### Requirement: 改名验证接入 Harness 统一验收

Harness SHALL 在每次统一验收时以演练方式校验改名脚本的有效性，且不要求模板仓库自身处于已改名状态。

#### Scenario: 闸门演练通过
- **WHEN** 运行 `harness\run-all.ps1`，且改名脚本工作正常
- **THEN** 改名闸门在临时目录完成改名演练与残留扫描，以退出码 0 结束，整体验收不受影响

#### Scenario: 改名脚本失效
- **WHEN** 改名脚本缺失、演练执行失败或演练后扫描到旧名残留
- **THEN** 改名闸门以非 0 退出码结束，`run-all.ps1` 整体判定失败
