# Design

## Context

见 `proposal.md` 的 Why。需要补两条设计约束：

- `docs/specs/wanderchain/` 的单元文档统一采用六段结构，§5.3 是固定的"响应式"小节、§5.5 是"与现状的差异"表。改这两节不能破坏既有骨架，否则 10 份文档的结构齐平会被打破。
- `harness/checks/` 下的脚本由 `run-all.ps1` 按文件名排序自动接入，两条约定：通过 `exit 0`、不通过 `exit 1`、全程不交互。脚本含中文，PowerShell 5.1 必须带 UTF-8 BOM，否则按 GBK 解码直接 ParserError（已发生过一次）。

## Goals / Non-Goals

**Goals:**

- u6、u8 两份文档的断点、列数、图片方案描述与实现一致
- 建立一条可复用的机械校验：文档声明的断点集合必须等于对应 CSS 的媒体查询断点集合
- 让"文档声称与实现一致"这类自证句失去生存空间——闸门只认文件，不认文字

**Non-Goals:**

- 不实现 u1–u5、u7、hero 文档里描述的响应式意图，也不改写这 6 份文档
- 不校验 `sizes` 字符串。它是断点的函数，正确性只由浏览器实测决定（`optimize-home-images` 的 4.2 已确立这条边界），机械化比对会与真实渲染值打架
- 不修改任何 `.module.css`

## Decisions

### D1：闸门的定位锚点用文档里的"真相源"声明行，不用正则猜哪些数字是断点

备选方案与取舍：

- **全量扫 `≥NNNpx`**：会误伤 `≥44px`（触控目标高度）、`≥ 10000`（浏览量阈值）这类非断点数字，u8 §4.1 就有一条
- **HTML 注释包一段标记块**：需要 `<!-- breakpoints:start -->` / `end` 成对出现，易被误删，且对读者无意义
- **在 §5.3 写一行"真相源：`xxx.module.css`"，闸门从该行扫到下一个 `###` 标题**（选用）

选它的理由：读者本来就需要知道断点出自哪个文件，这行不是为闸门而加的额外负担；而且它同时表达了"以谁为准"，未来换文件时有明确落点。

配套约束：脚本内另维护一张显式配对表（文档 → CSS），与文档里的真相源行交叉验证。这样删掉真相源行不能让文档静默退出校验。

### D2：断点数字统一写成累进 `max-width` 语义

实现是 desktop-first：默认铺满列数，再用 `max-width` 逐级收窄。文档原来写 `≥768px 两列` 是 mobile-first 语义，与实现方向相反，读者会误以为是从窄往宽叠加。

统一写法：

```
| `≤ 640px` | 1 |
| `≤ 900px` | 2 |
| `> 900px` | 3 |
```

闸门取数规则：

- 文档侧：`[<>≤≥]\s*(\d+)px` 提取数字集合
- CSS 侧：`max-width:\s*(\d+)px` 提取数字集合
- 两个集合必须相等

u6 得 `{640, 900}` ↔ CSS `{900, 640}`；u8 得 `{720, 1080}` ↔ CSS `{1080, 720}`。

**取舍**：集合相等是弱断言——它发现不了"断点值对但列数写错"。选它是因为列数无法稳定解析（表格结构会变、有的文档不用表格），而任何一侧增删断点都必然破坏集合相等。列数正确性留给人工审查与验收清单。

### D3：`320px` 不参与断点校验

`320px` 是最窄视口基准，不是媒体查询断点，CSS 里没有对应规则。因此验收行写成「320px 视口无横向滚动」，不加 `≥` / `≤` 前缀，闸门的正则自然跳过。

### D4：§5.3 只写现状，Tailwind 目标不在这里翻译

§5.2 已经有 `grid-cols-1 md:grid-cols-2 lg:grid-cols-3` 这类目标态示例，`md` / `lg` 的语义自带，不需要再在 §5.3 里翻译成 `768px` / `1024px`。保留两套数字正是这次漂移的成因。

## Risks / Trade-offs

- [集合相等抓不到列数写错] → 文档表格里同时保留列数列，人工审查仍可发现；闸门只负责抓"数字整体漂移"这一类
- [只覆盖 u6/u8，其余 6 份继续漂移] → 已在 proposal 写明范围限定与原因；闸门机制成型后，后续 change 只需往配对表加一行
- [删掉真相源行即可绕过闸门] → 脚本内配对表独立于文档，文档侧缺行会直接报错
- [PS 5.1 无 BOM 导致中文脚本 ParserError] → 用 `UTF8Encoding($true)` 写文件，首跑前核对首字节为 `EF BB BF`
- [改 §5.3 时破坏六段结构] → 只替换 §5.3 表体与 §5.4/§5.5 段落内容，标题层级与相邻小节一字不动
