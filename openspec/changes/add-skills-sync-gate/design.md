# Design

## 决策 1：只约束自研技能，排除 `openspec-*`

实测四层里六个 `openspec-*` 目录全部存在差异（12/12 DIFF），这是各工具生成的适配差异，不是漂移。若把它们纳入，闸门会在每次 `openspec update` 后误红。排除规则用目录名前缀 `openspec-*`，其余目录自动纳入。

## 决策 2：用「相对路径集合 + SHA256」而不是文本 diff

跨平台行尾（CRLF/LF）与编码差异会让文本比较产生噪声；哈希比较的是字节，与「逐字节一致」的约束一一对应。文件集合单独比较，保证副本多出或缺少文件都能被捕获。

## 决策 3：副本多出文件也判红

只查「真源有的副本也有」会允许副本偷偷携带额外脚本或文档，行为分叉依然成立。因此比较的是完整集合，多出即失败。

## 决策 4：闸门只报告，不自动同步

护栏只具备否决权。自动把真源覆盖到副本会掩盖「有人直接改副本」这个事实，也会让 agent 在不知情时改掉三个适配层。修复动作由人或明确的任务执行。

## 风险

- 首次运行应为绿（基线已实测一致）；若未来有人直接改副本，闸门会红并打印差异文件。
- 新增自研技能时忘记同步三处副本，会立即被闸门拦截——这正是期望行为。
