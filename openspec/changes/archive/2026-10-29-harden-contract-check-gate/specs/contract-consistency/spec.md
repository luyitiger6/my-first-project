# Spec Delta

## MODIFIED Requirements

### Requirement: 字段名与类型双向一致

契约闸门 SHALL 对每一对受管的后端 DTO 与前端契约文件做双向比对：接口名集合 MUST 相等，共有接口的字段名集合 MUST 相等，且每个共有字段的两侧类型 MUST 落在同一张公开的 Java↔TS 类型映射上。任一侧出现对方没有的接口或字段、或共有字段类型不匹配时，闸门 MUST 以非 0 退出码结束并指出接口名与字段名。接口名与字段名的存在性比对 MUST 大小写敏感，仅大小写不同的名字视为两个不同的名字。

#### Scenario: 两侧完全一致时通过

- **WHEN** 后端每个受管 record 的组件名与类型，与前端契约中同名 interface 的字段名与类型逐一匹配映射表
- **THEN** 闸门以退出码 0 结束，并报告受管接口数与字段数

#### Scenario: 字段类型漂移被判失败

- **WHEN** 后端把某字段从字符串类型改成整数类型，而前端契约仍声明为字符串
- **THEN** 闸门以非 0 退出码结束，并指出发生类型不匹配的接口名与字段名

#### Scenario: 字段名漂移仍被判失败

- **WHEN** 后端重命名某 record 组件，而前端契约未同步
- **THEN** 闸门以非 0 退出码结束，并分别列出后端有而前端无、前端有而后端无的字段

#### Scenario: 时间字段必须是 ISO-8601 字符串

- **WHEN** 后端某字段是时间戳类型（序列化为 ISO-8601 字符串），而前端契约把它声明为数值
- **THEN** 闸门以非 0 退出码结束，因为映射要求时间类型对应字符串而非数值

#### Scenario: 接口名漂移被判失败

- **WHEN** 后端存在某受管 record 而前端契约没有同名 interface，或前端存在某 interface 而后端没有同名 record
- **THEN** 闸门以非 0 退出码结束，并分别列出后端有而前端无、前端有而后端无的接口名

#### Scenario: 同名字段跨接口类型漂移被判失败

- **WHEN** 同一字段名在两个不同接口中出现，且某一对同名接口里该字段的两侧类型不一致（扁平比对会被另一接口里的同名字段覆盖而漏判）
- **THEN** 闸门以非 0 退出码结束，并指出发生类型不匹配的接口名与字段名

#### Scenario: 字段名大小写漂移被判失败

- **WHEN** 后端某字段名与前端对应字段名仅大小写不同（例如后端 `userId`、前端 `userid`）
- **THEN** 闸门以非 0 退出码结束，按大小写敏感判定为「后端有而前端无」与「前端有而后端无」两个不同字段名

### Requirement: 字段命名风格强制 camelCase

受管契约两侧的字段名 MUST 一律小写字母开头的 camelCase。任一侧出现蛇形或其它非 camelCase 命名，闸门 MUST 以非 0 退出码结束并指出字段名。

#### Scenario: 出现蛇形命名

- **WHEN** 后端 record 组件名或前端契约字段名含有下划线或以大写开头
- **THEN** 闸门以非 0 退出码结束，并指出不符合 camelCase 的字段名

#### Scenario: 前端字段非 camelCase 被判失败

- **WHEN** 前端契约的某 interface 字段名以下划线开头、含下划线或以大写字母开头，而后端对应字段命名合规
- **THEN** 闸门以非 0 退出码结束，并指出前端不符合 camelCase 的字段名
