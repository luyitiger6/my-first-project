# Design

## Context

见 `proposal.md` 的 Why。设计约束有三条来自仓库本身：

- 主规格 `wanderchain-homepage` 的「英文界面语言」要求界面 `MUST NOT` 出现中文字符，草稿层文档里的中文期望文案与之冲突时，以主规格为准。
- `harness/checks/08-spec-doc-breakpoints.ps1` 只校验 4 对文档与 CSS，且要求两侧 `max-width` 断点集合**完全相等**；u8 在配对表内。
- 前端测试跑在 jsdom 上，没有浏览器导航与真实布局引擎，「点击锚点跳转」这类行为无法被断言。

## Goals / Non-Goals

**Goals:**

- 6 条未覆盖场景归零，且每条都有可复查的证据（代码、断言或文档措辞）。
- 优先集约 20 条断言落地，覆盖数值格式化、竞态、会话生命周期三类易回归面。
- 保持九道闸门全绿，尤其 08 的断点集合相等约束。

**Non-Goals:**

- 不做 61 条全量断言补齐。
- 不修改任何主规格。
- 不引入 Playwright 等浏览器测试基建。
- 不改动登录/注册页的视觉与布局。

## Decisions

### 1. 错误文案改文档，不改代码

主规格要求界面零汉字，`page.test` 与 `/search` 测试都断言了可见文本不含中文。把 `useAiAssistant` 的抛错文案改成中文，会让这两条断言的前提自相矛盾。文档是草稿层，主规格是真相层，冲突时改草稿。

**备选**：改代码为中文并放宽断言——被否，等于让真相层让步于错误文档。

### 2. 占位页补站点框架，登录/注册保持独立

`PlaceholderPage` 是被首页两张功能卡指向的落地页，没有顶栏意味着用户进去后只能靠浏览器后退。补 `SiteHeader`/`SiteFooter` 是修复真实可用性缺陷。登录/注册是独立双栏品牌页，加顶栏会破坏其视觉意图，因此在文档里写成显式例外。

**备选**：把框架提到 `layout.tsx` 全站统一——被否，会改变登录/注册的版式；只改文档不改代码——被否，占位页仍然回不来。

### 3. 新增 480px 断点，而不是把 720px 改单列

720px 覆盖到竖屏平板，直接单列会让平板损失信息密度。480px 是手机竖屏档，与 u6 的 640px、u5 的 640px 属于同一量级但不重叠，符合各单元自选断点的既有做法。

该断点必须与文档**同一次修改**落地，否则 08 立即变红。

**备选**：复用 640px 与 u6 对齐——被否，u8 是五列网格，640 处从两列掉到一列跨度过大；文档 §5.3 也明确写了「不要为统一而改本单元断点」。

### 4. 锚点场景降级为「不作保障」，不补假断言

jsdom 不执行片段导航，写一条「点击后不报错」的断言无法区分「浏览器正确处理」与「组件根本没坏」，属于伪造绿灯。改为在文档中标注该行为由浏览器负责，本单元只在锚点目标存在时保证跳转。

**备选**：加 e2e——被否，本轮不引入新基建。

### 5. 断言按「归属层」分配，不堆在组件测试里

- 数值与文案格式化：留在组件测试，用固定 Mock 断言渲染结果。
- 会话生命周期与 SSR 守卫：放 `lib/auth/mock-auth.test.ts`，纯函数可直接构造过期/损坏会话。
- 重复提交与两次密码不一致：新建 `auth-form.test.tsx`，需要 mock `next/navigation` 的 `useRouter`，照 `account-menu.test.tsx` 的写法。
- 上下文缺失抛错：在 `ai-assistant.test.tsx` 内新增不包 Provider 的渲染用例。
- 竞态丢弃：在组件测试里用可控 Promise 模拟「先发的慢请求后返回」。

### 6. 优先集只取 20 条，不做全量

61 条里多数是静态属性与文案，回归概率低；优先集挑的是「数值会算错、竞态会串数据、会话会失效」三类，这三类一旦坏掉，视觉验收也看不出来。

## Risks / Trade-offs

- **占位页加框架后版式塌陷** → `PlaceholderPage` 目前靠自身 `min-height` 撑满视口，加了 header/footer 后会出现双倍高度与多余滚动；实现时改为由外层 flex 容器接管，并在 320px 与桌面两档各看一次。
- **480 断点与文档不同步导致 08 变红** → 把 CSS 与文档放在同一个提交、同一批任务里；跑 `08-spec-doc-breakpoints.ps1` 单独确认一次。
- **新增测试暴露既有缺陷** → 若断言失败指向实现问题（例如排名在个位数时不补零），按 `systematic-debugging` 先定位再改，禁止改成迎合测试的弱断言。
- **`auth-form.test.tsx` 的 router mock 不稳** → 直接照抄 `account-menu.test.tsx` 已验证的 mock 形态，不自创写法。
- **断言数量增加拉长前端测试时长** → 预计新增约 20 条，相对现有 208 条增幅约 10%，04 闸门耗时可控。

## Migration Plan

单次提交完成，不分阶段：样式与文档同批、组件与测试同批。回滚按文件粒度即可，无数据迁移、无外部依赖变更。
