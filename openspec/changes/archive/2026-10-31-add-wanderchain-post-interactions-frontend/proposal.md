# Proposal

## Why

帖子后端已有评论、投票、收藏接口，但前端广场仍使用 Mock，统计行也不能操作，用户尚无法完成真实互动。需要建立从真实帖子广场进入详情、登录后互动、刷新后恢复个人状态的闭环。

## What Changes

- `/posts` 接入真实 `GET /api/posts`，保留三种排序、URL 同步、无限滚动及失败重试；真实帖子以 `publicId` 导航至 `/posts/[publicId]`。
- **BREAKING**：广场卡片与数据查询契约从首页 Mock 模型迁往帖子域真实契约，替代“换数据源无需修改组件”的承诺。真实 API 没有英文摘要、作者显示名、城市与浏览数：不伪造、不强转、不混用 Mock 数字 ID；封面、标题、标签、作者对外标识、创建时间和三项统计组成基础卡片，呈现细节先确认再实施。
- 新增真实详情页：正文、封面、标签、三项统计；游客可读已发布内容，作者可读自己的草稿，其他人不能识别草稿。草稿详情不开放互动操作。
- 详情集中提供评论、二级回复、删除自己的评论、赞成/反对/取消投票、收藏/取消收藏；写失败保留输入，不伪造成功，成功后按服务端数据重新校准。
- 必要后端配套：补齐详情三项统计；增加受保护的当前账户互动状态读取；修正评论列表的父评论对外标识解析；评论和个人状态读取继承帖子详情可见性，防止草稿内容从附属接口泄漏。
- 显式修订旧规格中的三个冲突：评论未登录的 `401` 与正文 `400` 矛盾、`parentId` 与真实 DTO `parentPublicId` 不一致、取消反对票不应扣减赞成票数；收窄“所有帖子 GET 公开”为明确公开读登记，保留个人状态 GET 的认证边界。
- 互动登录入口携带安全的站内详情回跳地址；登录/注册互转保留该地址，无合法回跳参数时沿用回首页。不自动重放登录前的写操作。
- 视觉沿用英文 UI、CSS Modules、`--wc-*` 令牌及现有页头页脚。按用户最新放行的快速 MVP 规则，当前前后端只负责功能实现、同名契约对齐和本次真实操作链路调通；既有登录、注册及已通过结果直接复用，只在改动影响或出现相关故障时针对性复查。所有单测、自动化集成测试、E2E、测试文档、截图覆盖和全量 Harness 后置到用户需要时集中处理，不阻塞 MVP 功能调通，不为延期项伪造通过。排障仅解决当前业务阻塞，不为无关底层机制、字节码、二进制或非阻塞细节开展研究及额外工具工程。
- 用户于本轮明确放行仅本地账户初始化：缺少专用账户时，允许一次性非 prod 工具生成两组随机资料，复用已有测试用图形码签发、开发 Outbox 及真实注册服务；保留验证码校验、口令哈希和会话登记，不直写数据库、不清共享存储、不新增 HTTP 读码接口。初始化不算真实注册 UI 验收，随后仍须经前端代理正常登录并用 `/me` 确认本人。

范围之外：发帖/编辑帖子 UI、评论编辑、评论投票、无限层级回复 UI、个人收藏列表、作者资料查询、首页 Mock 内容迁移、实时推送、富文本/Markdown 渲染、样式体系迁移及历史无关规格修补。具体交互细节登记在 `design.md`，实施到关联任务前暂停确认；本次只生成规划工件，不实施、归档、提交或推送。

## Capabilities

### New Capabilities

- `wanderchain-post-interactions-frontend`：真实帖子详情与评论、二级回复、本人删除、投票、收藏的前端闭环，包含身份、竞态、错误和可访问性边界。

### Modified Capabilities

- `wanderchain-post-feed`：真实广场数据契约、真实卡片字段和详情入口，保留既有排序及分页行为。
- `wanderchain-posts`：补齐详情统计，明确公开读和受保护个人状态读的路径归属。
- `wanderchain-post-interactions`：当前账户互动状态查询、正确父标识与跨页回复关系、读取可见性及两处错误语义修订。
- `wanderchain-auth-frontend`：互动入口的安全登录/注册回跳，不改变会话真源与既有认证错误分流。

## Impact

- 前端：`app/posts/`、新增详情路由、`components/posts/`、新增 `lib/posts/` 请求与视图适配层、`lib/contracts/posts.ts`，以及认证表单中的安全回跳处理。首页 `lib/home/` 的 Mock 数据与 `HotPosts` 展示保持独立。
- 后端：帖子详情 DTO/映射、帖子互动 service 接口/实现/model、独立 Controller 与 DTO、必要 repository 查询及对应 service/controller 测试；新增 `backend/tools/SeedPostsAccounts.java` 非 prod 一次性初始化器，由 `scripts/seed-posts-accounts.ps1` 生成并注入随机账户环境变量、执行工具。密码不写文件或日志。复用现有表，不引入新表或迁移框架，不扩大认证拦截器公开通配范围。
- API：拟新增 `GET /api/posts/{publicId}/interactions/me`，只返回当前令牌账户的 `voteDirection` 与 `bookmarked`；`PostResponse` 增加三项非负统计。既有互动写接口、分页响应、错误码集合保持不变。
- 工作区：CHANGE 内五份 delta spec 的业务行为不变；实施先更新入口与任务的增量验证节奏。帖子广场与详情测试文档、`docs/e2e/`、独立真实联调 Playwright 配置及 `08` CSS/断点配对留到用户需要完整验收时处理，保留原桩套件；DTO 镜像变更时按需由 `10` 核对，不重复运行已通过且未受影响的检查。
- 第三方依赖：复用已有 Next.js/React（路由与状态）、Spring Web/JPA/Jackson（HTTP、查询与序列化）、Vitest/Testing Library/Playwright（测试）；本地初始化器复用现有 Spring Boot 容器及认证服务，随机资料使用 JDK/.NET 密码学随机源。不新增运行期、UI 或样式依赖。依赖可用性由 `01-compile` 与 `04-frontend` 验证。
