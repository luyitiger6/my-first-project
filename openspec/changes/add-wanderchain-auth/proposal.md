# Proposal

## Why

wanderchain 目前只有前端自包含的 Mock 认证：账号存在浏览器 localStorage，密码明文，令牌是 `alg: none` 的假 JWT，且生产构建下直接被拒绝。后端没有任何认证能力，因此「谁在调用」这件事在服务端从未被确立过。

本项目后端将正式连接数据库与其他中间件，认证成为一切用户态数据（会话、消息、用量）的前置门禁。先把认证的行为契约定死——尤其是**用户状态机**与**响应安全边界**——再谈实现，否则后续每个业务模块都要重复回答同一批问题。

引入认证的直接动因是后续的**社区分享（帖子与经验）**能力：帖子需要作者署名，作者需要可追溯且稳定的标识，而「作者注销后这些帖子归谁、怎么显示」会在社区上线当天变成设计问题。因此认证必须先于社区落地，且身份标识的稳定性属于认证的契约范围。

## What Changes

- 新增后端认证能力：图形验证码、注册码换发、注册（注册即 `active` 并自动登录）、登录、登出、查询当前用户、注销账号、邮箱验证码找回密码。
- 确立用户三态状态机：`active`、`email_unverified`、`deleted`，并规定状态迁移的唯一合法路径与迁移触发者。
- 确立登录响应的状态码映射：`200` / `401` / `403`，并规定**判定顺序**（先验凭证、后判状态），使该映射不成为账户枚举器。
- 确立**不锁用户**的防爆破策略：登录失败只触发账户维度（连续失败后要求图形码）与来源维度（超阈 `429` + `Retry-After`）限流，MUST NOT 使账户进入不可登录状态。来源定义为经可信代理链解析的客户端 IP（IPv6 按 `/64` 聚合），无法确认时单独计数而不得绕过。
- 保留 `email_unverified` 作为合法状态值，但本变更内无入口也无出口；后续引入产生该状态的入口时 MUST 同时交付出口。
- 确立响应安全边界：响应 MUST NOT 包含 `password_hash`、`salt`、`verification_code` 及其明文值，出站统一经全局响应包装；本变更先覆盖用户信息接口，其余端点后续补齐。密码与验证码以单向哈希形态持久化。
- 新增注册验证码链路：图形码校验通过后才投递邮箱注册码；注册码存共享缓存（最多 5 分钟，验证成功即删），注册提交时与缓存比对。重发受冷却限制，两层码均一次性。同一邮箱的发码总量受日配额约束（默认 5 封/自然日，注册码与重置码合并计数）。
- 引入后端持久化与中间件依赖：用户与会话需要落库；图形码、注册码、重置码、重发冷却与登录限流计数由共享缓存承载。运行时复用本机既有 MySQL 8（`127.0.0.1:8806`，本产品专属 schema `wanderchain`）与 Redis 7（`127.0.0.1:6606`，独立 db index + 前缀），不新建容器；凭据由环境变量注入，不写入仓库。不引入迁移框架：表结构由受版本控制的 `schema.sql` 在启动时幂等建出，本阶段库内无需保留数据，改结构直接 drop 重建。
- 令牌采用 JWT，并保留服务端校验点，使「注销与改密后立即失效」不被无状态签名架空。令牌经 `HttpOnly` + `SameSite=Lax` cookie 下发（响应体不含令牌，有效期绝对 7 天不滑动），不做 refresh token；写请求另做 Origin 校验防 CSRF。
- 新增密码找回：复用图形码 + 邮箱重置码链路，重置成功使全部旧令牌失效，账户状态不变。
- 本变更只交付 auth 核心（注册、登录、当前用户、登出、注销、密码找回与状态机）。邮件投递先接模拟发码程序，不接真实邮件服务；不改动社区模块，也不改造全站响应包装。

## Capabilities

### New Capabilities

- `wanderchain-auth`: wanderchain 后端的认证契约——用户状态机、三态对应的登录响应码、不锁用户的限流策略、响应字段安全边界、令牌签发与失效语义、注册与找回密码的验证码链路。该能力只描述**行为契约**，不描述具体持久化表结构或中间件选型。

## Impact

- **代码**：`backend/` 新增认证领域、Web 接入层与持久化层；`frontend/` 的 Mock 认证接入真实接口属后续独立变更。
- **依赖与运行环境**：后端从「无外部中间件」转为「依赖数据库 + 其他中间件」，`mvn test` 与本地启动的前置条件随之改变；Harness 中关于后端运行期边界的既有断言需要重新对齐。
- **API**：新增 `/api/auth/**` 一组端点，经前端同源代理 `/api/[...path]` 原样透传状态码，因此 `403`、`429` 会被浏览器侧直接看到。
- **既有规格冲突（本次不处理）**：`openspec/specs/database-baseline/spec.md` 中「后端运行期不依赖数据库」的 Requirement 与本变更方向相反。按本次决定，该能力不纳入本变更的 delta，归档前需单独修订，否则主 spec 会与实现互相矛盾。
- **非目标**：第三方登录、多因素认证、角色与权限模型、前端真实认证接入。
