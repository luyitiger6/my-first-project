采用「单入口 + 编号检查脚本」的扁平编排结构：`run-all.ps1` 作为唯一入口，扫描 `harness/checks/*.ps1` 并按文件名排序，以独立 `powershell.exe -NoProfile -ExecutionPolicy Bypass` 进程逐个执行，收集每个 check 的退出码与耗时；默认遇错早停（可通过 `-ContinueOnError` 跑完全部），最终输出 `[PASS]/[FAIL]` 摘要并以 exit 0/1 表达通过/阻塞。

`checks/` 下各闸门职责单一且相互独立，仅通过约定好的 exit code 通信：
- `00-submodule-check`：只读校验 `.gitmodules` 中 `backend`/`frontend` 两个 gitlink 已初始化且 HEAD 与父仓库一致；
- `01-compile` / `02-test`：在 `backend/` 分别执行 `mvn compile -DskipTests` 与 `mvn test`；
- `03-static-guard`：正则扫描 `backend/src/**/*.java` 与 `frontend/**/*.{ts,tsx}`，拦截 TODO/FIXME/XXX、`System.out.println`、`@Disabled`、`it.skip/describe.skip/test.skip/xit/xdescribe`；
- `04-frontend`：在 `frontend/` 串行执行 `npm ci → npm run build → npm run test`；
- `05-scaffold-check`：在 `$env:TEMP` 下的 GUID 临时目录复制工作区并运行 `scaffold/rename.mjs --name scaffold-demo --display 'Scaffold Demo'`，验证 `.gitmodules` 未被改写且旧身份 (`AIWorkSpace`/`ai-workspace`) 无残留；
- `06-schema-check`：依赖既有 `127.0.0.1:8806` MySQL 8 + 专用 schema 执行迁移；
- `07-doc-consistency`：校验 `AGENTS.md` 中 `<!-- harness-checks: ... -->` 标记与实际 `harness/checks/*.ps1` 文件一一对应，并扫描 `AGENTS.md`/`README.md` 中已下线技术栈 token；
- `08-spec-doc-breakpoints`：单元文档声明的断点与实际 CSS 媒体查询一致；
- `09-redis-check`：既有 `127.0.0.1:6606` Redis 可达、凭据正确、db 3 可选中；
- `10-contract-check`：前后端认证契约的接口名与字段名双向比对。

依赖方向单向：orchestrator → checks；check 之间不互相引用，也不修改自身所在仓库状态（需要改名的场景一律在临时目录副本中操作并在 finally 中清理）。
