根目录本身不含业务代码，而是三层编排的装配点：
- 工件层 `openspec/` 通过 spec-driven 规范产出 proposal/specs/design/tasks，作为变更的唯一真相源；`AGENTS.md` 与 `README.md` 定义 AI 进入本仓库的契约。
- 能力层 `harness/run-all.ps1` 按文件名排序依次执行 00~05 六个 PowerShell 检查脚本（子模块初始化 → 后端编译 → 后端测试 → 静态红线扫描 → 前端构建/测试 → 改名脚手架演练），任一退出码非 0 即阻断，是整条链路的完成判定依据。
- 行为层 `.agents/skills/` 为自研技能的 source of truth，分发到 `.claude/.qoder/.opencode/skills/` 供各 AI 工具消费。
- `backend/` 与 `frontend/` 通过 `.gitmodules` 以 gitlink 锁定提交，工作区不跟踪其文件内容，仅负责版本锚定与编排；应用身份（包名、artifactId 等）在各自子模块内管理，根目录 `scaffold/rename.mjs` 只改自身文档 slug 与展示名。
- 标准流程 `propose → apply → harness → archive` 由 AGENTS.md 强制约束，人工审阅位于 propose 之后、apply 之前，是唯一不可省略的卡点。
