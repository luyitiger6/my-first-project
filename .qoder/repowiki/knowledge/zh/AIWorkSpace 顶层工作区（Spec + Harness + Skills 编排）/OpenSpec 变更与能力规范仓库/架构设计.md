采用 OpenSpec 的 `spec-driven` schema，根级 `config.yaml` 声明全局上下文（中文输出、保留英文结构标题与 SHALL/MUST 关键字）。目录分为两层：
- `changes/`：按变更编号命名的活跃或归档变更集，每个变更包含 `.openspec.yaml`（schema + created 日期）、`proposal.md`、`design.md`、`tasks.md`，以及可选的 `specs/<capability>/spec.md` 能力规格；当前活跃变更 `add-db-baseline-and-flyway-gate` 对应数据库基线与 Flyway 闸门。
- `archive/`：历史变更按 `YYYY-MM-DD-<slug>` 命名归档，结构与 active 一致，便于追溯。
- `specs/`：独立于变更的能力规格集合（frontend-nextjs、skill-distribution、workspace-layout、workspace-scaffold），作为跨变更复用的能力契约。
依赖方向单向：变更通过 `specs/<capability>/spec.md` 引用能力规格，不反向引用；`.openspec.yaml` 是 OpenSpec CLI 识别变更的唯一入口。
