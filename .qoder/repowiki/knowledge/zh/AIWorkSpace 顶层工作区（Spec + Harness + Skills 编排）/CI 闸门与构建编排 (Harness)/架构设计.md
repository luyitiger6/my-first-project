采用「单入口 + 编号检查脚本」的扁平编排结构：`run-all.ps1` 作为唯一入口，扫描 `checks/` 下所有 `*.ps1` 并按文件名排序依次以独立 `powershell.exe -NoProfile -ExecutionPolicy Bypass` 进程执行，收集每个 check 的退出码与耗时，默认遇错早停（可通过 `-ContinueOnError` 跑完全部），最终输出 `[PASS]/[FAIL]` 摘要并以 exit 0/1 表达通过/阻塞。

`checks/` 下的六个闸门职责单一且相互独立：
- `00-submodule-check`：只读校验 `.gitmodules` 中 `backend`/`frontend` 两个 gitlink 已初始化且 HEAD 与父仓库一致；
- `01-compile`：在 `backend/` 执行 `mvn compile -DskipTests`；
- `02-test`：在 `backend/` 执行 `mvn test`（禁止跳过）；
- `03-static-guard`：正则扫描 `backend/src/**/*.java` 与 `frontend/**/*.{ts,tsx}`，拦截 TODO/FIXME/XXX、`System.out.println`、`@Disabled`、`it.skip/describe.skip/test.skip/xit/xdescribe`；
- `04-frontend`：在 `frontend/` 串行执行 `npm ci → npm run build → npm run test`；
- `05-scaffold-check`：在临时目录复制工作区并运行 `scaffold/rename.mjs --name scaffold-demo --display 'Scaffold Demo'`，验证 `.gitmodules` 未被改写且旧身份 (`AIWorkSpace`/`ai-workspace`) 无残留。

依赖方向单向：orchestrator → checks；check 之间不互相引用，仅通过约定好的 exit code 通信。
