### AIWorkSpace
- 定义：本顶层工作区的展示名与 slug；自身只沉淀「AI 编码如何被约束」的骨架（OpenSpec 工件 + Harness 闸门 + Skills 行为），前端与后端作为两个独立 git 子模块挂载，业务功能刻意极简。改名通过 `node scaffold/rename.mjs --name <slug> --display "<名称>"` 完成，只改 AGENTS.md 与 README.md，不改 `.gitmodules` 与子模块 URL。
- 别名：ai-workspace

### Harness
- 定义：项目的能力层（可执行护栏），位于 `harness/`，由 `run-all.ps1` 总控六道闸门（00 子模块 → 01 编译 → 02 测试 → 03 静态红线 → 04 前端 → 05 改名演练 → 06 Flyway）。完成判定只看退出码 0，人类审阅与 CI 均不认日志措辞。
- 别名：闸门、harness

### OpenSpec
- 定义：项目的工件层（spec-driven），变更走 `/opsx:propose` → 产出 `proposal.md` / `specs/` / `design.md` / `tasks.md` → 人工审阅放行 → `/opsx:apply` 实施 → `/opsx:archive` 归档。`openspec/specs/` 只收录已归档能力的规格，在飞变更的 delta 位于 `openspec/changes/<change-id>/specs/`。
- 别名：SDD、spec-driven

### Skills
- 定义：项目的行为层，真源位于 `.agents/skills/`，分发副本同步到 `.claude/skills/`、`.qoder/skills/`、`.opencode/skills/`。修订顺序固定为「先改真源 → 再同步三处副本」，禁止直接改副本。内置 systematic-debugging 与 verification-before-completion 两个自研强制技能。
- 别名：skills、行为层

### 工作区身份
- 定义：由 `--name`（slug）和 `--display`（展示名）组成的标识，用于在 AGENTS.md、README.md 等文档中替换项目名称；改名脚本拒绝同值执行、拒绝非法 slug、拒绝超长 display，且不会触碰 `.gitmodules` 与子模块 URL。
- 别名：workspace identity、工作区 slug

### 子模块边界
- 定义：`backend/` 与 `frontend/` 是独立 git 仓库，工作区只以 gitlink 锁定其提交；所有改动必须在对应子模块仓库内提交并推送，再回工作区提交新的 gitlink。工作区提交只包含自有文件、`.gitmodules` 与两个 gitlink；Harness 不自动暂存、提交或推送任何子模块。
- 别名：submodule boundary

### 运行期数据源
- 定义：应用代码对数据库的实际访问（DataSource/JPA/Hibernate）。本项目明确本期不接运行期数据源，Todo 仍走内存实现；数据库迁移与 Flyway 闸门属于「迁移所有权」，与运行期数据源是两件事。
- 别名：runtime datasource

### 同源策略
- 定义：前端对 `/api/*` 的请求由 Next.js Route Handler 接收并转发至运行期配置的后端地址（默认 `http://localhost:8989`），开发与生产使用同一实现；代理透传方法、请求体、状态码与响应体，不缓存上游响应，后端无需开放 CORS。
- 别名：same-origin proxy

### 构建期生效
- 定义：指 `BACKEND_URL` 在 `next.config.ts` 求值阶段注入镜像，而非运行期读取；因此换后端需要重新构建产物。与之相对的是「运行期可切换」的 Route Handler 代理方案，后者改环境变量后重启进程即可。
- 别名：build-time injection

### 护栏空洞
- 定义：某个关键验收环节没有被 Harness 闸门覆盖，导致错误可能流入主干。例如容器镜像构建不进 Harness、接入数据库后未把「起容器」纳入闸门等。
- 别名：guard gap
