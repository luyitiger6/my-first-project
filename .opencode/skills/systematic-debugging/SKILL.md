# 系统化排障（四阶段根因法）

## 何时触发

- 测试红了、启动报错、接口返回不符合预期
- 已经「修」了一次但问题没消失，或换了个地方复现
- 说不清为什么好使，只能反复试

## 核心纪律

**猜测即失败。** 没有证据的改动一律视为噪声，即使它刚好让测试变绿。

## 阶段一：复现（Reproduce）

1. 找到**最短**复现路径：一条命令、一个测试用例、一个请求
2. 记录**完整**错误输出，不要截断堆栈
3. 确认复现是稳定的：连续跑 3 次结果一致
4. 若无法稳定复现，先解决「不可复现」问题，不要往下走

产出：一句可以粘贴复现的命令 + 完整报错。

## 阶段二：最小化（Minimize）

1. 逐步剥离无关代码，直到剩下能触发问题的最小集合
2. 优先验证「边界」：空值、零、负数、超长、并发、编码
3. 对比工作版本与故障版本的差异，差异点就是嫌疑范围

产出：一份最小复现用例。

## 阶段三：定位根因（Root Cause）

1. 提出**一个**可证伪的假设，例如「问题在 X 层，因为 Y 条件不满足」
2. 用日志、断点或一次性打印验证该假设（验证后立即删除临时输出）
3. 假设被证伪就换下一个，**不要**在证伪后继续打补丁
4. 追问三次「为什么」，直到到达不再需要解释的层次

判据：能说清「改这里为什么必须让现象消失」，而不是「改了之后好像好了」。

## 阶段四：验证修复（Verify Fix）

1. 原本的复现命令必须由红转绿
2. 为这个 bug **补一个回归测试**，且先确认它在修复前会失败
3. 跑全量护栏：`powershell -File harness\run-all.ps1`
4. 检查是否引入副作用：相邻功能、边界输入

## 反模式清单

| 反模式 | 为什么有害 |
|---|---|
| 加 try-catch 把异常吞掉 | 现象消失，根因留下 |
| 调大超时 / 重试次数 | 掩盖竞态，压力下必然复发 |
| 注释掉失败的断言 | 护栏被拆，等于没写测试 |
| 一次改五处 | 即使修好也说不清哪处生效 |
| 「重启一下就好了」 | 未解释的状态残留 |

## 收尾

问题解决后，在对应的 OpenSpec change 里记录：根因、影响面、回归测试位置。
没有记录根因的修复，等于给下一个人埋雷。
